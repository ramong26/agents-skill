# 예약 서비스 본문 샘플 forward test 보고

## 수행

- `development-plan-review/SKILL.md`와 연결된 `references/document-design.md`, `documents:documents`, `pdf:pdf`를 읽고 적용했다. 스킬 파일은 변경하지 않았다.
- 요청의 순서를 요구사항 → REQ-01 예약 생성 → REQ-02 CSV 내보내기 → 기술스택 → 검색 화면 → 예약 처리 화면으로 유지했다. 표지, 목차, 12장 구성은 만들지 않았다.
- `reservation-sample.docx`와 `reservation-sample.pdf`를 실제 생성했다. PDF는 DOCX 변환본이 아니라 같은 내용을 별도로 조판한 출력이다.
- PDF 최종본을 Poppler 150dpi PNG 3장으로 렌더하고 `final-page-1.png`부터 `final-page-3.png`까지 모두 직접 열어 검토했다. 표 다음 소제목과 그림 다음 설명이 밀착된 초기 출력은 간격을 늘린 뒤 재생성·재렌더·재검토했다.
- `build.py`는 생성 재현용, `check.py`는 내용·서체·크기·영역을 확인하는 실행 가능한 검사이며 최신 결과는 `check.log`에 남겼다. 의존성을 설치하지 않았다.

## 페이지와 크기

- PDF는 실제 A4 세로 595.2756 × 841.8898pt의 3쪽이다. 최종 PNG는 모두 1241 × 1754px다. 미리보기에서 여백이 잘려 표시되는 것과 실제 페이지 크기는 구별했다.
- 1쪽은 요구사항과 REQ-01 상세, 2쪽은 REQ-02·기술표·간단 검색 화면, 3쪽은 복잡 예약 처리 화면과 설명이다. 복잡 화면을 독립 페이지에 두었고 글자를 축소해 합치지 않았다.
- PDF 실제 텍스트 크기는 10.5, 11, 14, 18pt다. 본문 11pt, 표 10.5pt, 소제목 14pt, 제목 18pt다. 화면 라벨은 원본 27px를 폭162mm로 배치하여 인쇄 환산 최소 11.27pt다.
- A4 여백 위25mm·아래22mm·좌우24mm를 지정했다. PDF 텍스트 좌표가 해당 영역 안에 있는지 assert로 확인했다.

## 서체

- 지정 Pretendard는 조사한 번들·저장소·Windows 사용자 폰트 위치에서 찾지 못했다. 실제 출력은 기존 Windows `malgun.ttf`와 `malgunbd.ttf`를 사용했다. **지정서체 Pretendard 적용은 미검증이며 이 샘플은 서체 기준을 완전히 충족하지 않는다.**
- DOCX Normal/Heading 1/Heading 2 기본 스타일과 직접 서식을 준 run에 `Malgun Gothic` 영문·동아시아 서체를 지정하고 OOXML에서 확인했다. 표 run에도 동일 서체와 10.5pt를 확인했다. 화면 그림도 맑은 고딕으로 그렸다.
- PDF 리소스에는 `AAAAAA+MalgunGothic`와 `AAAAAA+MalgunGothicBold`가 확인되었다. ReportLab의 기본 Helvetica 리소스도 남지만 실제 텍스트 크기·한글 렌더와 맑은 고딕 사용을 함께 확인했다. 서체명만으로 한글 대체 여부를 추정하지 않았다.

## 내용과 배치 검증

- REQ-01/REQ-02의 기능 상태는 둘 다 `확정`으로 유지했다. 중복 판단 시간범위와 보유기간은 표 아래 ID별 확인사항으로 분리했다. 미정 세부사항 때문에 기능 전체를 미정으로 바꾸지 않았다.
- 날짜·요청번호 입력, 동일 요청번호 검사, 중복 차단, 승인 대기 저장, 승인 시 확정, 반려 의견 필수, 저장 실패 시 입력 유지와 재시도, 중복 차단 및 승인/반려 이력 검수 조건을 본문에서 대조했다.
- REQ-01은 역할·입력·처리·오류·완료 기준을 짧은 굵은 라벨로 나누고 순차 처리 3단계를 각각 줄로 분리했다. 상태 셀에 긴 설명을 넣지 않았다.
- React/FastAPI/인프라 미정을 보존했다. 미정 분야를 채우려고 새 기술을 추가하지 않았다. 미제공 내보내기 세부 규격과 검색 결과 방식은 확정 기능으로 만들어내지 않고 확인사항으로 표시했다.
- 검색 화면은 테두리 입력란과 버튼 모양으로, 복잡 화면은 요청번호·날짜·승인 대기·저장·승인·반려 의견·반려·실패 안내·재시도를 실제 그림에 배치했다. 대괄호 버튼 대용 표기는 없다.
- PDF 최종 3쪽에서 한글 누락, 겹침, 잘림, 제목 고립, 문장 꼬리, 표 행 분할을 발견하지 않았다. 표는 모두 해당 쪽 안에 끝나며 반복 머리글과 행 분할 금지를 DOCX에 지정했다. 요구 ID와 표 2개·화면 그림2개를 구조 검사했다.
- 표 다음 소제목에 최소9mm 여백을 확보하고 그림과 설명 사이4mm를 두었다. 핵심 라벨·확인사항에는 굵기와 강조색 `#245A81`을 적용했다. 흑백에서도 라벨·굵기·테두리로 구별된다.
- 화면별 독립 페이지 규칙은 복잡 화면에만 적용했다. 소량 내용으로 생긴 2·3쪽 하단 여백을 새 기능이나 장식으로 채우지 않았다.

## 제약과 판정

- 공식 `render_docx.py`를 실행했으나 `FileNotFoundError: LibreOffice soffice.exe was not found on PATH`로 실패했다. `docx-render.log`에 로그를 보존했다. 의존성 로더가 번들 LibreOffice 경로를 제공하지 않았고 설치도 하지 않았다.
- **DOCX의 실제 페이지 수·줄바꿈·최종 시각 품질은 미검증이다. DOCX와 PDF의 동일 렌더도 미검증이다.** DOCX는 내용·OOXML 스타일·행 분할 설정 검사만 통과했다. PDF 시각 검증 결과를 DOCX 시각 검증으로 대신 주장하지 않는다.
- 판정: 요구 내용 보존과 PDF 가독성의 제한적 forward test는 통과했다. 지정 Pretendard 적용과 DOCX 렌더 게이트는 충족하지 못하여 완전한 문서 납품 품질 통과로 볼 수 없다.
