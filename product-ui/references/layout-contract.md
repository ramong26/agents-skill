# Layout Contract

컴포넌트 유무와 관계없이 레이아웃 책임, 정보 계층, 반응형 동작을 일관되게 유지하기 위한 기준이다. 아래 수치는 프로젝트에 유효한 기준이 없을 때만 쓰는 기본값이다.

## 기준 선택 순서

1. 현재 프로젝트의 semantic token
2. 가장 가까운 기존 화면에서 반복되는 패턴
3. 이 문서의 기본 기준표
4. 화면 범위에 격리한 최소 local style

기존 값을 무조건 덮어쓰지 않는다. 한 번 나온 값보다 여러 관련 화면과 공용 스타일에서 반복되는 값을 우선한다.

## 콘텐츠 폭과 페이지 여백

| 화면 유형 | 기본 콘텐츠 최대 폭 |
| --- | ---: |
| form | 360–480px |
| list/table | 1120–1280px |
| dashboard | 1120–1280px |
| detail | 720–960px |
| settings | 720–960px |
| mixed | 핵심 업무에 맞는 위 범위 |

- 데스크톱 좌우 여백: `24px`
- 좁은 화면 좌우 여백: `16px`
- 폼은 불필요하게 전체 폭을 사용하지 않는다.
- 목록과 표의 중요한 정보를 임의로 숨기지 않는다.

프로젝트에 대응하는 spacing 또는 container token이 있으면 숫자를 직접 추가하지 않고 그 토큰을 사용한다.

## 의미 관계별 간격

| 관계 | 기본 간격 |
| --- | ---: |
| 아이콘과 텍스트 | 4–8px |
| label과 input | 8px |
| 같은 그룹의 요소 | 8–12px |
| 폼 필드 사이 | 16px |
| 제목과 설명 | 8px |
| 제목과 콘텐츠 | 16px |
| 독립된 섹션 사이 | 24–32px |
| 주요 화면 영역 사이 | 32–40px |

간격은 요소 크기가 아니라 관계로 고른다: 같은 의미 그룹은 작게, 같은 업무 흐름은 중간, 다른 업무 영역은 크게 둔다. 한 간격 값을 화면 전체에 반복하지 않는다.

## 크기와 타이포그래피

| 요소 | 기본값 |
| --- | ---: |
| 일반 input/button | 44px |
| 조밀한 표 내부 컨트롤 | 36–40px |
| 주요 CTA | 44–48px |
| 아이콘 버튼 | 최소 40px |
| 페이지 제목 | 24–28px |
| 섹션 제목 | 16–18px |
| 본문 | 13–14px |
| 보조 정보 | 12–13px |

- 같은 화면의 일반 input과 button 높이는 기본적으로 맞춘다.
- 본문 행간은 글자 크기의 약 1.5배에서 시작한다.
- 굵기는 대체로 400, 500, 600 안에서 의미 역할별로 구분한다.
- 텍스트 길이가 아니라 페이지 제목, 섹션 제목, 본문, 보조 정보의 역할로 크기를 정한다.
- 폰트 패밀리는 프로젝트 설정을 따른다.

## 레이아웃 책임

```text
페이지 좌우 여백       → Page Container
콘텐츠 최대 너비       → Content Container
섹션 사이 여백         → Section Layout
세로 요소 간격         → Stack 또는 부모 gap
가로 요소 간격         → Cluster 또는 부모 gap
컴포넌트 내부 여백     → 컴포넌트 자체
폼 필드 간격           → Form Layout
테이블 셀 여백         → th / td
```

`Container`, `Stack`, `Cluster` 컴포넌트가 없어도 같은 책임을 semantic HTML과 기존 CSS로 유지한다.

```text
Page
└─ Container
   └─ Section
      ├─ SectionHeader
      └─ SectionContent
```

컴포넌트는 외부 margin을 소유하지 않는다. 일회성 wrapper를 이 이름에 맞추기 위해 추출할 필요는 없다.

## 카드와 표

- 카드는 독립된 객체나 경계가 필요한 작업 영역에만 사용한다.
- 페이지 전체, 모든 섹션, 이미 카드인 영역의 내부를 다시 카드로 감싸지 않는다.
- 표는 `SectionHeader → TableContainer → table` 구조를 사용한다.
- `table`, `thead`, `tbody`, `th`, `td`의 의미를 유지한다.
- 텍스트는 왼쪽, 비교 수치는 오른쪽 정렬한다.
- 표 헤더는 40–42px, 데이터 행은 48–52px, 셀 좌우 패딩은 12–16px에서 시작한다.
- 좁은 화면에서는 정보 열을 임의로 숨기지 않고 표 영역만 가로 스크롤한다.

## 반응형 조정 순서

1. 페이지 좌우 여백 축소
2. 가로 간격 축소
3. 자연스러운 줄바꿈 허용
4. 다중 열을 세로로 배치
5. 넓은 표나 데이터 영역만 가로 스크롤

데스크톱과 모바일에서 핵심 정보의 순서와 주요 행동을 유지한다.
