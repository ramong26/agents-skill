# Anti-slop Fallback

`kill-ai-slop` 스킬을 실제로 호출할 수 없을 때만 사용하는 수동 검수다. 자동 스캐너 실행이나 전체 taxonomy 검사를 했다고 간주하지 않는다.

## 절차

1. 구현한 화면과 관련 스타일·카피만 범위로 잡는다.
2. 가능하면 데스크톱과 좁은 화면을 실제 브라우저에서 본다.
3. 아래 항목을 코드와 렌더링 결과에서 확인한다.
4. 각 후보를 의도된 디자인인지 AI 기본 패턴인지 판별한다.
5. 의도와 기능을 보존하는 최소 수정만 적용한다.
6. 같은 화면과 상호작용을 다시 확인한다.

## 검사 항목

- 의미 없는 gradient, 배경 glow, 색이 들어간 shadow
- 요소 크기에 비해 과도한 그림자 또는 border와 큰 shadow의 중복
- 모든 요소의 과도한 둥근 모서리, glassmorphism, pill 남용
- 카드 안의 카드와 화면 전체를 카드로 감싼 구조
- badge, 상태 pill, 아이콘 타일과 장식 아이콘 남용
- 장식용 eyebrow·kicker와 의미 없는 01/02/03 표식
- 출처 없는 통계 카드와 화면을 채우기 위한 데이터
- 페이지 제목·섹션 제목·본문이 구분되지 않는 평평한 타이포그래피
- 모든 관계에 같은 간격을 적용한 구조
- 일관성 없는 컨테이너 폭과 섹션보다 더 크게 벌어진 내부 요소 간격
- 구체성이 없는 과장 카피, 반복되는 구호, 장식용 emoji
- 테두리와 radius가 서로 다른 박스에 있어 모서리 선이 끊기는 구조
- hover scale, `transition-all`, 중심이 흔들리는 spinner 같은 무의미하거나 잘못된 motion
- 모바일에서 핵심 콘텐츠나 행동을 무작정 숨기는 구조

## 보존할 의도

다음은 존재한다는 이유만으로 제거하지 않는다.

- 사용자가 명시했거나 기존 토큰에 정의된 브랜드 색상과 폰트
- 의도된 로고, 일러스트, 제품 고유 장식
- 접근성 또는 상태 전달에 필요한 색상과 motion
- 실제 측정값과 의미 있는 status badge
- 해당 제품의 명확하고 반복되는 디자인 결정

의도가 불분명하면 자동으로 제거하지 않는다. 사용자 확인이 필요하거나 유지한 이유가 불확실하다는 점을 최종 보고에 적는다.

## 결과 기록

- 수동 fallback을 사용한 사실
- 확인한 화면 크기와 상태
- 수정한 후보와 유지한 의도적 표현
- 브라우저, 카피 언어, 동적 상태 등 확인하지 못한 범위
