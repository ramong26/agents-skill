# 개발 기획서 문서 디자인

초안 작성과 최종 조판에 공통 적용한다. 기존 목차·장 순서·업무 흐름·기능·완료 조건은 유지하고 표현과 배치만 정리한다. 참고 문서는 폰트·위계·목록·표·간격의 참고로 사용한다. 사용자 지정 서식·색상을 우선하고 기존 인쇄 규격과 최소 글자 크기를 유지한다.

## 페이지 구성

- 표지: 큰 제목 `프로젝트명 개발기획서`와 `담당자: 김수연 | 날짜: YYYY년 M월 D일` 두 요소만 배치한다. 담당자는 사용자가 변경하면 그 값을 사용하고 날짜는 지정일, 없으면 작성일을 쓴다. 부제·버전·설명 문단·도식은 넣지 않는다.
- 두 번째 페이지: 기존 목차 항목·순서·점선·쪽번호 형식을 유지하고 최종 PDF의 실제 쪽수와 맞춘다.
- 장 시작: 장 번호·제목·핵심 요약을 일관된 형식으로 둔다. 장마다 별도 페이지를 강제하지 않는다.
- 본문: 아래 기준으로 표·리스트·도식을 선택한다. 실제 날짜가 미정이면 일정은 단계·의존 관계로 표시한다.
- 내용이 적은 페이지: 관련 내용을 합치거나 흐름을 재배치한다. 의도적인 여백은 유지하고 빈 공간을 채우기 위한 장식·반복 설명은 추가하지 않는다.

## 독자가 읽는 표현

- 근거·출처 열, 원문 제목·절·쪽번호, 내부 대조 기록은 납품 본문에서 제외한다. 검토용 기록은 내부 전달에만 사용한다.
- 소스 파일 경로·파일별 코드 위치·구현 조사 기록은 제외하고 사용자 기능·처리·결과로 설명한다. 필수 데이터 규격과 API 계약은 해당 설계 장에서 유지한다.
- 확정 내용은 자연스러운 문장으로 쓴다. 제안·미정 내용은 필요한 곳에만 `설계제안: 짧은 설명`, `확인사항: 결정할 내용`으로 쓴다. `[원문의 목표]`, `[확인된 사실]`, `[설계 제안]` 같은 대괄호 라벨은 쓰지 않는다.
- 화면 그림의 버튼은 버튼 모양으로, 입력은 테두리 있는 입력란으로 표현한다. `[저장]`, `이름 [ ]` 같은 텍스트 대용 표기는 쓰지 않는다. 기술 문법에 필요한 대괄호는 임의 삭제하지 않는다.

## 내용에 맞는 배치

| 내용 | 표현 | 구성 |
|---|---|---|
| 개발 범위·향후 기능 | 기능별 소제목과 리스트 | 기능명 아래 주요 동작·결과·제외 조건을 짧게 나열 |
| 요구사항 비교·권한·데이터 항목 | 표 | 같은 속성을 열로 두고 한 행에 한 항목 |
| 기능 상세·핵심 로직·비기능 조건 | 소제목과 리스트 | 처리·오류·완료 조건을 구분; 비교가 필요한 부분만 표 |
| 기술스택 | 분야별 표 | 분야 / 기술 / 용도; 프론트엔드·백엔드·데이터 저장·인프라·외부 API로 구분 |
| 절차·아키텍처·일정 | 도식·타임라인 또는 일정표 | 기존 순서·분기·의존 관계 유지 |
| 화면안 | 정적 와이어프레임과 짧은 설명 | 실제 위치 관계는 그림으로, 설명은 그림 밖에 배치 |

기술스택에서 미정 분야는 `미정`, 제안 기술은 기술명 옆에 `설계제안`을 적는다. 표를 채우기 위해 새 기술을 추가하지 않는다.

## 글꼴·색상·표

- 본문은 검정 `#151A20`, 장 제목·기능 소제목은 네이비 `#1A304B`와 굵기로 구분한다. 기본 강조색은 파랑 `#245A81`, 보조 설명은 회색 `#66727E`로 둔다.
- 핵심 완료 조건·중요 제한·확인사항은 짧은 구절에 굵기와 강조색을 적용한다. 긴 문단 전체를 칠하지 않는다. 필요하면 연한 배경 `#EEF3F8`의 안내 영역으로 묶는다. 상태 의미는 텍스트로 함께 적는다.
- 표 머리는 네이비 바탕과 흰 글자, 본문 셀은 흰색 중심으로 구성한다. 옅은 구분선과 선택적인 교대 행 배경으로 읽는 방향을 돕는다.
- 리스트는 한 항목에 한 동작·조건을 적고 들여쓰기와 항목 간격을 통일한다. 소제목과 다음 내용의 간격을 일정하게 유지한다.

표에는 비교할 수 있는 짧은 정보를 두고, 긴 처리·오류·완료 기준은 표 밖에서 요구 ID로 연결한다. 열 너비는 내용 길이에 맞추고 반복 머리글을 적용한다. 셀 테두리와 채움색은 정보 구분에 필요한 만큼만 사용한다. 글자를 줄여 표를 맞추지 않는다.

예: 긴 요구사항 표는 `ID / 요구사항 / 입력과 결과`로 줄이고 표 아래에서 같은 ID별로 `처리 / 오류 / 완료 기준`을 설명한다. 근거 표시는 제외하되 기능과 검수 조건은 유지한다.

## 렌더링 검토

표지·본문·상세 명세 샘플에서 제목·강조·표·리스트·그림의 위계와 읽는 순서를 확인한다. 전체 조판 후 축소본으로 반복 구성과 빈 공간을 찾고 원래 크기로 글꼴·줄바꿈·대비·라벨 크기를 확인한다. 디자인 변경 전후의 목차·업무 흐름·기능·완료 조건이 같은지 대조한다.
