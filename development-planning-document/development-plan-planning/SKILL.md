# 개발 기획서 기획 파트

총괄 에이전트가 제공한 원문과 공통 범위를 바탕으로 01 프로젝트 개요, 02 요구사항 정리, 10 일정과 개발 파이프라인, 11 비기능 요구사항, 12 향후 개발 요구사항의 **내용 초안**을 반환한다. 개발 설계·기능 상세·아키텍처·화면·최종 파일 제작은 맡지 않는다.

## 작성

1. 원문과 사용자 지시를 구분한다. 참고 기획서의 문체·상세도는 참고할 수 있지만 그 안의 프로젝트 사실은 가져오지 않는다.
2. 핵심 주장마다 사실·목표·제안·미결정을 내부적으로 구분하고 출처 대조 기록은 본문과 분리한다. 납품 본문에는 목표를 문장으로 설명하고 제안·미정 사항만 `설계제안:`, `확인사항:`으로 짧게 표시한다. 목표를 실적이나 계약상 완료 기준으로 바꾸지 않는다.
3. 01에는 배경, 사용자, 해결할 업무, 결과물, 사업 목표의 상태를 적는다. 02에는 범위 내 요구사항에 안정적인 ID를 부여하고 입력·결과·검수 가능한 조건을 연결한다. 제외 범위를 명시하고 개발 담당과 ID를 공유한다.
4. 10에는 원문 일정의 단계·의존성·산출물·확인 지점과 개발 납품 파이프라인을 적는다. 근거 없는 기간·인력·비용은 채우지 않는다.
5. 11에는 개인정보·권한·안전·품질·운영 등 실제 자료에서 확인되는 비기능 요구만 적는다. 수치가 없는 항목은 임의 목표치 대신 검수 방법과 결정할 값을 적는다.
6. 12에는 MVP 이후 후보와 이번 범위에서 명시적으로 제외된 기능을 구분하고, 도입 조건·미결정 사항을 붙인다.

## 총괄 에이전트에 전달

담당 장의 초안과 함께 `요구사항 ID·짧은 제목·범위` 목록, 내부 검토용 출처 목록, 장 사이에 영향을 주는 충돌, 계약 전 확인 사항을 전달한다. 서로 다른 수치의 측정 대상·시점·표본이 다르면 차이를 설명한다. 근거가 부족한 조건은 질문으로 남기되, 확인된 내용은 먼저 작성한다.
