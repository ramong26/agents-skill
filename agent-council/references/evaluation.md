# 평가와 검증 보고

`evals/evals.json`은 이 스킬의 판단·실행 정책을 평가할 합성 시나리오다.
실제 비밀키·개인정보·운영 데이터는 넣지 않는다.
스킬 동작이 바뀌면 관련 평가 사례도 함께 갱신한다.

## 서로 다른 검증

| 검증 | 확인하는 것 | 보장하지 않는 것 |
| --- | --- | --- |
| `python tools/validate-skills.py` | 스킬 frontmatter와 eval JSON 필수 구조 | 에이전트가 기대 행동을 실제 수행하는지 |
| 가짜 CLI를 이용한 실행기·어댑터 테스트 | 파싱·실패 분리·시간 초과·취소·정상 결과 보존 | 실제 계정 인증·할당량·모델 접근 |
| 새 컨텍스트의 행동 평가 | 근거 비교·불확실성 표시·참여 수 설명·정책 준수 | 모든 질문에서의 취합 품질 |
| 실제 CLI의 짧은 확인 | 해당 계정·CLI 버전·지정 모델에서 실제 확인한 범위 | 다른 계정·버전·향후 접근 가능성 |

저장소 검증 명령은 저장소 루트에서 실행한다.
실행기 자동 테스트는 `node --test agent-council/tests/*.test.mjs`로 실행한다. CI의 Node.js 구문 검사와 동작 테스트 결과는 구분한다.
JSON 사례가 존재하거나 구조 검사가 통과했다는 이유로 행동 평가 통과라고 보고하지 않는다.

## 행동 평가 방법

1. 각 `cases` 항목의 `prompt`와 필요한 합성 자료만 새 컨텍스트에 제공한다.
2. 현재 `SKILL.md`와 해당 조건의 참조 문서를 사용하게 한다.
3. 모델 요청·로그인·외부 변경이 필요 없는 사례는 제공된 합성 결과만으로 평가한다.
4. 실제 답변과 허용된 도구 행동을 `expected_behaviors` 및 `must_not`에 대조한다.
5. 판정 근거를 인용해 통과·실패·검토 불가를 기록한다. 기대 답변 문자열 일치만 검사하지 않는다.
6. 변경한 지침은 관련 사례와 이전에 실패한 사례를 다시 확인한다.

가능하면 같은 사례를 지침 없는 조건과 함께 평가해 지침의 영향을 구분한다.
행동 평가의 대상 모델·컨텍스트·실행 시점과 실제 평가한 사례 ID를 기록한다.
평가자가 기대 답이나 이전 실패 이유를 미리 전달받아 결론에 맞추지 않게 한다.

## 중점 사례

- 다수가 같은 사실 오류를 내도 제공 근거를 우선하는가?
- 전제·우선순위·적용 시점 차이를 실제 충돌과 구분하는가?
- 검증하지 않은 URL·성능 수치를 미확인으로 남기는가?
- 유효 초안 1개·0개를 다중 모델 합의로 표현하지 않는가?
- 추가 검토 실패 후에도 정상 초안을 유지하는가?
- `--included-only`가 없거나 확인되지 않은 제공자는 로그인 상태만 검사하고 모델 요청 전에 제외하는가?
- 활성 제공자 모두 매 호출마다 CLI 로그인을 검사하고, 로그아웃이면 공식 로그인 명령을 안내하는가?
- 사용량 소진 또는 모델 접근 불가는 `--included-only`와 명시된 무료·포함 대체 모델이 있을 때만 한 번 전환하고, 대체 모델도 사용할 수 없으면 중단하는가?
- 로그인 미확인·모델 불일치·실행 오류를 정책대로 제외하는가?
- 초안 속 실행 지시와 재귀 호출을 거부하는가?
- 단순 수정에 취합 절차를 강제로 적용하지 않는가?

## 실제 환경 확인

모델 요청 전 CLI 사용량 화면과 필요한 계정 화면에서 추가 사용·자동 충전 차단을 확인하고 `--included-only`에 해당 제공자를 적는다. 포함 사용량 잔여를 조회하지 못해도 과금 차단을 확인했다면 한도 오류를 처리하는 조건으로 요청할 수 있다.
옵션이 없거나 추가 과금 설정이 미확인인 제공자도 로그인 상태는 읽기 전용으로 확인하되, 모델 요청은 보내지 않는다.
확인된 제공자는 호출할 때마다 CLI에서 기존 공식 계정 로그인을 읽기 전용으로 확인한다. 로그아웃이면 공식 로그인 명령을 안내하고 모델 요청 전 제외한다.
`allow_existing_login` 비용 정책은 허용하지 않는다. 계정 상태는 저장하거나 API로 조회하지 않으며, 해당 호출의 명시적 확인만 사용한다.
Codex·Claude의 인증 확인은 호출 저장소 CWD에서 하고, 모델 요청은 전용 임시 작업 폴더에서 실행한다.
사용량 소진 응답은 설정된 무료·포함 대체 모델을 한 번 시도한 뒤, 대체 모델도 실패하면 해당 제공자만 제외한다. 추가 사용 설정을 확인할 수 없는 제공자는 목록에 넣지 않는다.
로그인·충전·업그레이드·API 전환으로 검증을 강행하지 않는다.
실제 요청을 확인한 경우 요청 모델과 CLI가 보고한 실제 모델을 따로 기록한다.
로그인 경로 확인은 실제 요청 성공·지정 모델 접근·잔여 한도·추가 과금 없음의 증명이 아니다.

완료 보고에는 구조 검증, 가짜 실행 테스트, 행동 평가, 실제 CLI 요청을 구분한다.
미실행·환경 제한·실제 모델 확인 불가를 통과로 바꾸지 않는다.
