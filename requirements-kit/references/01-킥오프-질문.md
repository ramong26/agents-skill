# 킥오프 질문

요청을 받으면 바로 만들지 말고 이 질문부터 보낸다. 해당 없는 건 지운다.
★ = S 크기 작업에서도 꼭 묻는 질문.

---

## 복붙용

안녕하세요, [요청 이름] 작업 시작 전에 몇 가지 여쭤볼게요. 짧게 답해 주셔도 괜찮습니다.

**목적**
1. ★ 이걸 왜 만드나요? 지금 어떤 점이 불편하거나 문제인가요?
2. 이게 잘 되면 무엇이 달라지나요? (시간 절약, 실수 감소, 보고 등)

**사용자**
3. 누가 쓰나요? 권한이 나뉘나요? (관리자 / 일반 / 외부 거래처 등)
4. 얼마나 자주 쓰나요? (매일 여러 번 / 주 1회 / 월말에 몰아서)

**지금 방식**
5. 지금은 이 일을 어떻게 하고 계세요? (엑셀 / 수기 / 기존 시스템 / 아직 없음)
   — 쓰는 양식이 있으면 보내 주세요. 그대로 옮기려는 게 아니라 순서를 참고하려고 합니다.
   — 아직 없으면: 이 일이 생기면 어떻게 처리하실 생각인가요?
6. 그중 가장 번거롭거나 자주 틀리는 단계는 어디인가요? (이 부분을 줄이는 게 목표입니다)

**입력과 결과**
7. 이 화면에 들어올 때 손에 어떤 자료가 있나요? (서류, 숫자, 파일) 그 자료는 어떤 순서로 생기나요?
8. 끝나고 나면 무엇이 나와야 하나요? (저장된 기록, 출력물, 다른 사람에게 보내는 것)
9. 실제 예시 한 건을 알려 주실 수 있나요? (예: 최근에 처리한 건 하나의 숫자)

**성공과 범위**
10. ★ 사용자가 들어와서 무엇을 하고 나가면 "성공"인가요?
11. ★ 이번에 **하지 않는** 것은 무엇인가요? (모바일, 권한, 출력, 연동 등)
12. 참고할 화면이나 기존 시스템이 있나요?

**확인과 일정**
13. 최종 확인(승인)은 누가 하시나요? 중간 확인은 누구에게 드리면 되나요?
14. 언제까지 필요하신가요? 중간에 한 번 보여 드려도 될까요?

**SI 환경 (해당 시)**
15. 연동할 기존 시스템·DB가 있나요? 기존 데이터를 옮겨야 하나요?
16. 사용 환경은요? (브라우저, 사내망, 화면 크기)
17. 납품·검수는 어떤 방식으로 하나요? (시연, 테스트 결과표, 문서)

## 답 받은 뒤 스스로 점검

- [ ] "왜"에 대한 답이 기능 이름이 아니라 문제로 나왔다
- [ ] "안 하는 것"이 최소 1개 이상 나왔다
- [ ] 실제 예시 한 건(숫자 포함)을 받았다
- [ ] 확인해 줄 사람의 이름을 안다
- 하나라도 비면 → 1-pager의 `열린 질문`에 그대로 옮긴다
