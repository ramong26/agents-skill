# 확인 메시지

짧게, 답하기 쉽게. 질문은 "네/아니요"나 하나 고르기로 답할 수 있게 쓴다.

---

## ① 1-pager 확인 요청
```
○○님, [기능명] 만들기 전에 제가 이해한 내용을 한 장으로 정리했습니다.
[링크/첨부]

특히 아래 세 가지가 맞는지 봐 주세요.
1. 목적: [한 줄]
2. 입력 순서: [자료1] → [자료2] → [결과] (지난번 주신 [예시 건] 숫자로 채웠습니다)
3. 이번에 안 하는 것: [항목]

맞으면 "맞아요"만 답 주셔도 됩니다. 확인 주시면 그 내용대로 시작하겠습니다.
```

## ② 흐름 코멘트가 없을 때 (흐름만 따로)
```
○○님, 피드백 감사합니다. 말씀하신 [계산 항목]은 반영하겠습니다.
한 가지만 더 여쭤볼게요. 실제로 일하실 때 순서가 이게 맞나요?

[자료1]을 받으면 → [입력1] → [자료2]가 오면 → [입력2] → [결과 확인] → 저장

순서가 다르거나, 자료가 나중에 오는 경우가 있으면 알려 주세요.
```
> 고객은 글로 된 기획안에서 자기 업무 숫자에만 반응한다. 흐름은 따로 물어야 답이 나온다.

## ③ 변경 확인 (변경 관문)
```
○○님, [기능명]에서 처음 확인받은 내용과 달라지는 점이 있어 먼저 여쭙습니다.

- 처음: [확인된 내용]
- 바꾸려는 것: [변경]
- 이유: [한 줄]

괜찮으시면 바꾸고, 아니면 처음대로 진행하겠습니다.
```

## ④ 중간 시연
```
○○님, [기능명] 뼈대가 나와서 방향이 맞는지 먼저 보여 드립니다. (디자인은 아직 입니다)
[링크/캡처]

[예시 건]으로 처음부터 저장까지 해 봤습니다.
순서나 빠진 항목만 봐 주시면 됩니다.
```

## ⑤ 답이 없을 때
```
○○님, 지난번 [기능명] 정리본 확인 부탁드렸는데 혹시 보셨을까요?
[날짜]까지 답이 없으면 [기본안]으로 진행하고, 나중에 달라지면 그때 조정하겠습니다.
```
> 기본안으로 진행했으면 결정 로그에 "요청자 확인: 미회신, MM/DD 기본안 진행"이라고 남긴다.

## ⑥ S 크기 한 줄 확인
```
○○님, [요청]은 [이렇게] 바꾸고 [이건] 그대로 두려고 하는데 맞을까요?
```
