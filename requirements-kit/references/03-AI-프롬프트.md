# 단계별 AI 프롬프트

역할 구분: AI는 **빠뜨린 것 찾기 + 초안 만들기**. 의도를 확정하는 건 요청자다.
AI가 만든 질문·초안은 다듬은 뒤 반드시 요청자에게 확인받는다.

모든 프롬프트 끝에 붙이는 공통 문장:
> 모르는 부분은 그럴듯하게 채우지 말고 `[확인 필요: 무엇을 누구에게]`로 표시해 줘.

---

## ① 킥오프 질문 뽑기
```
아래는 요청자에게 받은 요청이야. 만들기 전에 요청자에게 물어볼 질문을 뽑아줘.
- 기준 질문 목록(첨부)에서 이 요청에 해당하는 것만 고르고, 이 요청에만 필요한 질문을 추가해
- 특히 "왜", "안 하는 것", "지금은 어떻게 하나", "손에 어떤 자료가 있나", "실제 예시 한 건"은 빠뜨리지 마
- 요청자가 개발자가 아니라고 생각하고 쉬운 말로 써줘
- 10개 이내, 중요한 순서로

[요청 내용 붙여넣기]
[01-킥오프-질문.md 붙여넣기]
```

## ② 메모·대화 → 1-pager 초안
```
아래 회의 메모/메신저 대화를 1-pager 양식(첨부)에 맞춰 정리해줘.
- 요청자가 실제로 한 말과 내가 추측한 것을 구분해 줘. 추측은 끝에 (추측) 표시
- 대화에 없는 항목은 비워 두고 7번 열린 질문으로 옮겨줘
- 범위 밖 항목이 대화에 없으면 "범위 밖이 아직 안 정해짐"을 열린 질문에 넣어줘

[메모/대화 붙여넣기]
[02-1pager.md 붙여넣기]
```

## ③ 흐름 그리기 + 예외 찾기
```
아래 1-pager의 핵심 흐름을 다음 형태로 만들어줘.
1. 표: 순서 | 사용자 손에 있는 자료 | 화면에서 입력·선택 | 화면에 나오는 결과
   - 요청자가 준 실제 예시 건의 숫자로 채워줘. 숫자가 없으면 [확인 필요]
2. Mermaid flowchart
3. 흐름마다 예외 케이스: 권한 없음, 빈 데이터, 자료가 아직 없음, 입력 오류, 서버 에러, 로딩, 중간에 나갔다 다시 옴
4. 화면 목록 표: 화면 | 데이터 | 동작

[1-pager 붙여넣기]
```

## ④ 로우파이 목업
```
아래 화면 목록과 흐름으로 로우파이 와이어프레임을 만들어줘.
- 회색 박스와 실제 예시 숫자만. 색·폰트·꾸밈 없이
- 화면마다 "요청자에게 물어볼 점"을 옆에 한 줄씩
- 배치 대안이 있으면 코드로 만들지 말고 목업으로 2개까지만 나란히 보여줘

[흐름 표 + 화면 목록 붙여넣기]
```
> 화면 대안을 코드로 바로 만들지 않는다. 코드로 바꾸는 게 싸면 확인 없이 계속 바꾸게 된다.

## ⑤ 리뷰어: 롤백될 만한 곳 찾기
```
너는 깐깐한 SI 프로젝트 리뷰어야. 아래 1-pager에서 나중에 롤백이나 재작업이 날 만한 곳을 찾아줘.
- 요청자 확인 없이 내가 정한 것
- 해석이 둘 이상 가능한 문장
- 흐름에서 순서가 정해지지 않은 곳
- 범위 밖이 불분명한 것
- 계산 결과를 실제 자료로 검증하는 기준이 없는 곳
각각 "왜 위험한지"와 "요청자에게 보낼 질문 한 줄"로 써줘. 위험한 순서로.

[1-pager 붙여넣기]
```

## ⑥ 1-pager → 완료 기준
```
아래 1-pager로 완료 기준 체크리스트를 만들어줘.
- 확인 가능한 문장으로만 (예: "필터 3종이 동작한다" O, "사용성이 좋다" X)
- 핵심 흐름을 예시 건으로 끝까지 실행하는 항목 포함
- 계산이 있으면 "요청자 실제 자료와 결과 일치" 항목 포함
- 범위 밖 항목은 "만들지 않음"으로 명시

```
